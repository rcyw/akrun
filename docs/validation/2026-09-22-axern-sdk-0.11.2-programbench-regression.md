## Cancellation, security, and cleanup

The reproduction exposed an independent Axrun lifecycle gap: top-level cancellation knew the
primary compile Run but not verifier-owned branch Runs. Commit `1fdb575` adds a narrow multi-Run
cancellation hook. The ProgramBench adapter now cancels persisted running steps and deletes its
derived Environment idempotently; it does not introduce a workflow engine or Snapshot resource.

For this pre-fix live reproduction, the branch was explicitly cancelled and the derived Environment
was deleted through the public SDK. All acceptance Runs were terminal, all five task/smoke
Environments created after the version reset were deleted, and the final Environment count was
zero. The task-scoped directory was moved to recoverable trash at
`/data/forge-artifacts/.trash/programbench-tty-clock-20260922-v0112`.

- credential/header marker scan: zero files;
- locked branch-blob digest scan in CandidateBundle storage: zero files;
- active Run count after cleanup: zero;
- no model credential or Tunnel was used.

No hidden test body, credential, token, private address, kubeconfig, or private API is recorded here.

## Acceptance status

The SDK/API upgrade itself is compatible: local contracts, the public runtime smoke, qualification,
CandidateBundle creation, compile rootfs result, derived Environment creation, and empty official
parity all passed with `axern-sdk==0.11.2`. Full deterministic ProgramBench acceptance remains
blocked only by Axern #177. After that issue is fixed in a fully published release, create new gold
and partial episode IDs and require exact test-level parity against the already locked official
evals; do not reuse the cancelled gold episode or report an observed-tests ratio as official score.
