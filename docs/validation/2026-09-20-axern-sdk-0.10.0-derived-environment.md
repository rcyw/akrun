# Axern SDK 0.10.0 derived Environment validation

## Scope

This validation upgrades Axrun to the released `axern-sdk==0.10.0` and checks the public
post-compile state boundary required by the locked ProgramBench official instance. It is a
capability acceptance, not an official ProgramBench evaluator or leaderboard result.

## Public contract audit

`tools/reproducers/programbench_post_compile_snapshot.py` now audits the exact released API rather
than inferring support from snapshot-like method names:

- `AxernClient.create_run` has an explicit `rootfs_snapshot` parameter whose default is `False`;
- `AxernClient.wait_rootfs_snapshot(run_id, timeout=...)` is public;
- the locked SDK version is exactly `0.10.0`.

The reproducer exits `0` only when all three conditions hold. A successful workload and its rootfs
result remain separate results. The snapshot result publishes an ordinary immutable Environment;
there is no mutable Snapshot resource.

## Live source-Compose truth path

The test used the released SDK against the running source-managed Compose cluster. The setup Run
used strict deny-all networking, removed `/etc/debian_version`, wrote a marker outside
`/workspace`, and set its mode to `0751`. Rootfs sealing returned a content-addressed derived
Environment. Two subsequent Runs were then created independently from that Environment.

## Remaining Axrun work

The Axern platform capability is no longer the blocker tracked by the historical stage-zero
record. Axrun still intentionally leaves `programbench-official-single@1` out of its executable
adapter catalog. The next implementation slice must add benchmark-owned orchestration for one
compile Run with rootfs sealing followed by one fresh Run per active test branch, then compare the
complete result against ProgramBench 1.2.4's official evaluator. Until that parity passes, Axrun
does not claim an official score.

No new Axern issue was filed. Existing Axern issue `#163` is closed, and this live validation found
no mismatch between the released SDK contract and the v0.10.0 source Compose server.

## Reproduction

With the source Compose context exported and the cluster configured with a rootfs snapshot
repository:

```bash
uv sync --locked
uv run python tools/reproducers/programbench_post_compile_snapshot.py
uv run pytest tests/test_programbench_official_stage_zero.py
```

The live test additionally requires an existing content-addressed base Environment. Create a
finite Run with `rootfs_snapshot=True`, wait for both `wait_run` and `wait_rootfs_snapshot`, and
then create at least two fresh Runs using the returned `environment_id`. Do not use `Sandbox.close`
for this flow because it cancels its long-lived Run instead of producing a successful finite-Run
rootfs result.
