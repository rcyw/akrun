# Released Axern v0.11.4 network-policy reacceptance

Status: **passed** on native `linux/amd64`. This is a public-SDK network-policy
smoke, not a benchmark episode. It rechecks the failure recorded for
[Axern #181](https://github.com/cofy-x/axern/issues/181) on released v0.11.3;
it does not test the separate Compose DNS doctor issue #182.

## Locked runtime and method

- Axrun evidence commit: `dcc49e06a634a7a76c9113ed9c9587865a35700d`.
- Axern release: CLI and local stack `v0.11.4`, release commit
  `44462793a5f6cc0e11daa5fe1ee5a7c67d6776f4`. The node image ID was
  `sha256:631a35469de04a53826d7d47635e54a19e7cc11576839abcc1b63ce4228bf25f`
  from the released `images.lock`, not a source-build candidate.
- Public PyPI `axern-sdk==0.11.4`; locked wheel SHA-256
  `9cb5b68e733de2ceb536451256fa6c099fa2159bb5e33dc99be1ffc8d1490b2f`.
- Task image: `index.docker.io/library/python@sha256:2d62568c3174136030ac1da4e534cfbfe709aec913daeb2a3d49328e27438093`.
- Fixed probes: body-free, TLS-verified GET `https://example.com/` requiring
  actual HTTP 200; direct IP TCP connect to `1.1.1.1:443` without DNS or proxy.
- Two paired trials were declared before execution; both completed. There was
  no retry-until-pass. Each trial used one Environment and fresh deny-all and
  unrestricted Runs/Allocations. The released SDK supplied `deny_all()` for
  the first Run and omitted the policy for the unrestricted control.

trials, and the original v0.11.3 stack and pre-existing Environment were
restored and confirmed healthy. No Axern adapter change was needed in Axrun.
